# 从失败证据到有效控制

采用 Git 中的薄索引、按主题的条目、可回放验证和正式事实源。正常任务不加载一整本 LESSONS，不需要数据库或额外服务。

## 1. 首次失败如何留下线索

先修当前任务。普通首次失败在已有任务记录 / PR / issue 中保留稳定的 failure category、触发路径、纠正证据链接和严重度；不另建每日学习日志。判断重复时按同一根因和修复方向归类，不能只数相似错误文本，也不能把同一尝试的重试算成多次事故。严重度由已发生的影响或实际逃逸证据确定。

至少两次独立同类失败，或一次高严重度逃逸，才建立条目。已有趋势需链接其观察样本，不能用主观感受代替证据。

## 2. 索引与条目

达到触发条件后才添加 `docs/experience/index.md` 和对应主题条目。索引每行只含 ID、状态、触发条件、排除条件、条目链接；workflow 在命中路径 / 风险时引用相关行。Candidate 仅在维护 / 评测场景召回，不能在普通执行时当成正式指令；retired 默认不召回。正文保留证据与评测，正式规则只在一个 Guide / Skill / Gate 中维护，条目链接它而不复制。

每条记录最小字段：

- 稳定 ID / failure category / 状态 / Owner。
- 既有失败证据链接、严重度、独立事件数量。
- 适用路径 / 场景、排除条件、期望输出。
- 分类落点：项目事实、复用方法、机械 Gate、语义 Sensor、确定性代码或一次性 task note。
- Candidate 变更 / 正式事实源、评测命令和证据、授权来源。
- 版本、回滚条件、复查触发条件 / 日期、替代 ID。

## 3. 生命周期与授权

`candidate → evaluated → active → retired`。不通过评测可回到 candidate 或标记 rejected。evaluated 只表示已有合格验证；active 还需要对应维护 / 发布授权。自主提出的候选不能自动覆盖正式控制。用户已明确要求维护该对象时，直接在范围内实现并验证，记录已有授权，不重复求批准。跨范围、费用、外部影响变化仍核对权限。

Gate / Sensor 晋级至少验证：原失败被检测、合法反例通过、配置 / 工具错误阻断、路由命中与非适用任务不误载。体验或业务语义另需来源独立的验收依据。正式规则变化时更新当前契约，历史 ADR / 条目证据保持可追溯。

## 4. Skill 效果如何证明

机械回放证明确定性控制行为，不能证明模型因 Skill 更好。Skill 候选使用固定任务集比较有 / 无 Skill：相同模型版本、输入、上下文预算、采样与工具权限；既包含失败任务，也包含合法反例、非适用任务和未见任务。重复运行并保留原始输出与版本。

按实际目标记录：任务成功率、同类错误率、误触发 / 误拒率、修复轮数、耗时与 token。评测前定义通过标准和允许成本，基于既有需求 / fixtures / 人工验收判断正确性；不只让候选作者自评。未运行或无足够证据就标记 `not-run` / `inconclusive`，不以“测试全绿”声称 Skill 收益。

## 5. 合并、失效与退役

按根因合并重复条目，保留事件来源和替代关系。依赖 / 入口 / 契约版本变化、误报、负向探针失效、A/B 无收益或成本过高时重评；无观察机会不等于有效。失效条目退出默认索引，标记 retired 和原因，保留可回溯历史。回滚正式规则要走同样的相关验证和授权，不能只删文字。

可运行样例：[experience-loop](../examples/experience-loop/README.md)。它回放本仓真实的扫描错误假绿，比较冻结的旧脚本与当前脚本；Skill 模型 A/B 明确未运行。
